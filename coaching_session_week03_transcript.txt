[STUDENT]:
Here is the getProjectDetails function from src/models/projects.js:

const getProjectDetails = async (id) => {
  const query = `
    SELECT 
      p.project_id,
      p.title,
      p.description,
      p.date,
      p.location,
      p.organization_id,
      o.name AS organization_name
    FROM service_projects p
    JOIN organizations o ON p.organization_id = o.organization_id
    WHERE p.project_id = $1;
  `;

  const queryParams = [id];
  const result = await db.query(query, queryParams);
  return result.rows.length > 0 ? result.rows[0] : null;
};

In this function:
- It takes an id parameter to find one specific project.
- In the SQL query, we use $1 as a placeholder instead of putting the id variable directly into the string. This is a parameterized query, which protects our database from SQL injection attacks.
- We pass [id] in queryParams to db.query(). The database library safely replaces $1 with the actual value.
- We check if result.rows has any items. If it does, we return the first row (the project object), or null if no project was found.

const showProjectDetailsPage = async (req, res) => {
    const projectId = req.params.id;
    const project = await getProjectDetails(projectId);
    const categories = await getCategoriesByProjectId(projectId);
    const title = project ? project.title : 'Project Details';

    res.render('project', { title, project, categories });
};

In our router (src/routes.js), we have the route defined as router.get('/project/:id', showProjectDetailsPage). 

Here is how the controller works:
- When a user goes to /project/5, Express extracts the number 5 from the URL and puts it into req.params.id.
- The controller saves that into projectId.
- It calls our model functions getProjectDetails(projectId) and getCategoriesByProjectId(projectId) to fetch the project data and its categories from the database.
- It sets the page title to the project's title if found.
- Finally, it calls res.render('project', ...) to send the data to the project.ejs template so the user sees the full detail page.

Here is the error-handling code from our server.js:

// Catch-all route for 404 errors
app.use((req, res, next) => {
    const err = new Error('Page Not Found');
    err.status = 404;
    next(err);
});

// Global error handler
app.use((err, req, res, next) => {
    // Log error details for debugging
    console.error('Error occurred:', err.message);
    console.error('Stack trace:', err.stack);
    
    // Determine status and template
    const status = err.status || 500;
    const template = status === 404 ? '404' : '500';
    
    // Prepare data for the template
    const context = {
        title: status === 404 ? 'Page Not Found' : 'Server Error',
        error: err.message,
        stack: err.stack
    };
    
    // Render the appropriate error template
    res.status(status).render(`errors/${template}`, context);
});

Our strategy has two main parts:
1. Handling 404 errors: If a user asks for a page or URL that does not match any routes in our router, the request falls through to the 404 catch-all middleware. It creates an error object with status 404 and passes it to next(err).
2. Centralized 500/global error handler: At the very bottom of server.js, we have Express error middleware with four parameters (err, req, res, next). It catches any error passed via next(err) or thrown in route handlers. It logs the error message and stack trace to the console for the developer. Then it sets the HTTP status code (404 or default 500) and renders our friendly custom error template (errors/404.ejs or errors/500.ejs). This way, the server never crashes, and the user gets a friendly message instead of a broken screen.
