----------------------------------------------------------------------
[STUDENT]:
Sure! Here is the query I use in my project to get all service projects with their organization and category details:

SELECT 
  p.project_id,
  p.title,
  p.description,
  p.location,
  p.date,
  o.name AS organization_name,
  c.name AS category_name
FROM service_projects p
JOIN organizations o ON p.organization_id = o.organization_id
LEFT JOIN categories c ON p.category_id = c.category_id
ORDER BY p.date ASC;

In our database:
- organizations stores the partner groups (like BrightFuture Builders).
- service_projects stores the actual volunteer events.
- categories stores types of service (like Environmental or Educational).

One organization can create many projects, so that is a one-to-many relationship using organization_id. We use an INNER JOIN with organizations because every project must have an organization. We use a LEFT JOIN with categories just in case a project doesn't have a category set yet, so it won't disappear from our list.

export async function getAllProjects() {
  try {
    const queryText = `
      SELECT 
        p.project_id,
        p.organization_id,
        p.category_id,
        p.title,
        p.description,
        p.location,
        p.date,
        o.name AS organization_name,
        o.logo_filename,
        c.name AS category_name
      FROM service_projects p
      JOIN organizations o ON p.organization_id = o.organization_id
      LEFT JOIN categories c ON p.category_id = c.category_id
      ORDER BY p.date ASC;
    `;
    const result = await db.query(queryText);
    return result.rows;
  } catch (error) {
    console.error("Error retrieving service projects:", error);
    throw error;
  }
}

This function sends our SQL query to PostgreSQL using db.query(). It waits for the database to finish using await, and then returns result.rows, which is an array of project objects. If something breaks, the catch block logs the error and throws it so our route handler knows there was a problem.

Now for Topic 3: Express Server Logic and Routing, can you show me the Express route handler where this function is called and describe how it routes the request?

----------------------------------------------------------------------
[STUDENT]:
Here is the /projects route from server.js:

app.get("/projects", async (req, res) => {
  try {
    const title = "Service Projects";
    const projects = await getAllProjects();
    res.render("projects", { title, projects });
  } catch (error) {
    console.error("Error loading service projects:", error);
    res.status(500).send("Error retrieving service projects");
  }
});

When a user visits /projects in their browser, Express catches that GET request. The handler calls getAllProjects() to get the data from the database, and then uses res.render() to pass the projects list and page title into our EJS view template. If the database fails, it returns a 500 server error message.

Here is a snippet from src/views/projects.ejs:

<div class="projects-grid">
  <% if (projects && projects.length > 0) { %>
    <% projects.forEach(project => { %>
      <article class="project-card">
        <div class="project-badge"><%= project.organization_name %></div>
        <h2 class="project-title"><%= project.title %></h2>
        <p class="project-desc"><%= project.description %></p>
        <div class="project-meta">
          <span>📍 <%= project.location %></span>
        </div>
      </article>
    <% }); %>
  <% } else { %>
    <p>No service projects found.</p>
  <% } %>
</div>

I used two kinds of tags:
- <% %> for JavaScript logic like if conditions and the forEach loop. These tags do work behind the scenes and don't print any text directly onto the page.
- <%= %> for outputting values like <%= project.title %> and <%= project.organization_name %>. This safely outputs the data as plain text and escapes special characters so users can't inject malicious code (preventing XSS attacks).
